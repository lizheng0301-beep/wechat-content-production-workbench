# 运行手册

## 启动前检查

1. 电脑网络正常，系统时间正确。
2. 本地配置文件仍在仓库外，DeepSeek、RightCode 和微信凭据非空。
3. 当前公网出口 IPv4 已在微信公众号白名单。
4. 端口 `8765` 没有被其他应用占用。
5. 昨天仍可用的 Key 通常不需要重配；只有 Key 被撤销、过期或配置文件丢失时才需要重填。

## 启动

```powershell
python app.py
```

出现以下两行代表服务已启动：

```text
WeChat Content Production Workbench running at http://127.0.0.1:8765
Local data: .../.workbench/workbench.sqlite3
```

打开 <http://127.0.0.1:8765/>。

## 演示前冒烟检查

按顺序执行，避免在演示中才触发长耗时任务：

1. 状态面板确认文本、图片、公众号均已配置。
2. 测试公众号连接，确认没有 `40164`。
3. 打开一篇现有草稿并保存。
4. 切换“编辑模式 / 排版预览”，确认正文和图片正常。
5. 对一小段内容生成一张图片，确认 RightCode 可用。
6. 打开创建草稿确认框，确认最终预览可加载；不要重复创建真实草稿。
7. 打开数据复盘。账号无分析权限时应显示真实错误或人工登记入口，不应出现演示数据。
8. 使用“导出工作台包”创建一次仓库外备份。

## 日常停机与重启

直接关闭启动服务的终端会停止本地服务。SQLite 每次写入自动提交，已有文章和素材不会因正常重启丢失。

自动配图任务是进程内任务。退出前等待任务完成，否则任务状态会丢失，之后需要重新发起。

## 备份与恢复

优先导出 ZIP 工作台包，它同时包含数据库内容和已经登记的素材文件。JSON 备份只包含结构化数据。

恢复前先导出当前数据。导入接口会替换受支持表的数据，并恢复包内素材；不要把来源不明的备份导入工作台。

## 故障处理

### 页面打不开

- 请求 `http://127.0.0.1:8765/api/status`。
- 若连接被拒绝，重新启动 `app.py`。
- 若提示端口占用，关闭旧进程或设置 `WORKBENCH_PORT` 使用其他端口。
- 桌面快捷方式失效时，先用命令行直接启动，区分“快捷方式问题”和“项目问题”。

### 自动配图长时间等待

- 图片模型是异步接口，生成和轮询可能持续数十秒到数分钟。
- 不要反复点击；同一草稿已有运行任务时服务会返回现有任务。
- 检查状态面板的图片配置，确认使用 `RIGHTCODE_IMAGE_API_KEY`。
- 超过配置的超时时间后查看提示，确认令牌余额、模型名和中转站任务状态。

### 微信连接失败

- `40164`：从错误信息中取得微信实际看到的 IPv4，更新白名单。
- `40013` 或凭据错误：核对 AppID 和 AppSecret，它们不是同一个值。
- 图片格式错误：安装 Pillow，重启后再试。
- 创建草稿失败时不会自动无限重试，避免网络异常造成重复草稿。

### 数据复盘没有数据

- 草稿不产生阅读数据，文章必须正式发布。
- 微信统计通常不是即时生成，只同步 D-7 至 D-1。
- 账号返回 `48001` 时，使用“后台数据手工登记”，数值必须来自公众号后台。
- 重复同步执行 upsert，不会把同一天数据重复相加。

## 回滚

代码更新前先保留 Git 提交和 ZIP 备份。代码回滚不会自动回滚 SQLite 数据结构；需要恢复数据时使用更新前导出的工作台包。
