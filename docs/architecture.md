# 架构说明

## 系统定位

公众号内容生产工作台是本地单用户应用。它用固定业务工作流组织热点、选题、写作、配图、排版、公众号草稿和发布后指标，不包含 Agent 编排、RAG、向量检索或模型微调。

## 组件

| 组件 | 实现 | 职责 |
| --- | --- | --- |
| 浏览器界面 | `index.html`，原生 HTML/CSS/JS | 页面状态、表单、轮询配图任务、展示预览与指标 |
| 本地服务 | `app.py`，`ThreadingHTTPServer` | JSON API、业务规则、模型/微信适配、备份恢复 |
| 本地数据库 | SQLite | 热点、选题、草稿、素材、投递任务和指标 |
| 本地素材 | `.workbench/assets/` | 来源图、模型生成图、本地信息卡 |
| 外部服务 | AI HOT、文本模型、图片模型、微信 API | 热点、生成、草稿和实际统计 |

服务固定监听 `127.0.0.1`。它不是公网 API 服务，也没有身份认证层。

## 核心流程

```text
AI HOT -> 热点缓存 -> 人工选题判断 -> 文本模型生成
       -> 规则质检 -> 排版校验 -> 来源图/模型配图
       -> 统一 HTML 渲染 -> 微信图片上传 -> 创建公众号草稿
       -> 人工正式发布 -> 登记文章 -> 微信统计/手工真实数据
```

### 生成与校验

文本提供商返回结构化 JSON。系统记录实际提供商、模型和是否使用备用模型。配置了文本模型但调用失败时，长文生成会报错；只有完全未配置文本模型时才使用本地协作模板。

排版模型只能增加受限的 Markdown 结构标记。服务端会比较排版前后的纯文本；文字被改写、结构超预算或结果无效时，改用本地排版规则。

质检包含 12 项确定性检查，并汇总为 5 个层面。它检查禁用词、首屏、篇幅、段落、证据、信息密度和重点标记等，不进行外部事实核查。

### 图片流程

自动配图先尝试当前选题来源页的正文图片，再补齐图片缺口。存在图片模型时调用 RightCode 或 OpenAI 兼容端点；没有图片模型时生成明确标记的本地信息卡。

自动配图任务保存在进程内存中，由守护线程执行。数据库只保存最终素材和正文结果，服务重启会丢失尚未完成的任务状态。

### 微信草稿

本地最终预览和微信草稿都调用 `md_to_html()` 与 `wrap_wechat_document()`。正式写入前，本地图片会上传到微信并替换为微信 URL。

`POST /api/drafts/{id}/publish` 的历史路由名保留为兼容接口，实际行为是创建草稿，不调用群发或发布接口。

## 数据模型

| 表 | 用途 |
| --- | --- |
| `source_item` | AI HOT 热点缓存和来源 |
| `topic` | 人工角度、读者、观察、经历、情绪和评分 |
| `draft` | 正文、摘要、标题候选、证据、声明、模型和质检 |
| `asset` | 素材路径、来源、版权备注、Prompt 和用途 |
| `publish_job` | 创建微信草稿的状态和 `media_id` |
| `published_article` | 人工确认的正式发布文章 |
| `metric_daily` | 按文章、日期、指标和来源唯一存储的日数据 |
| `metric_sync_run` | 数据同步范围、成功天数和错误 |
| `metric_record` | 旧指标表，当前汇总明确隔离 |
| `setting` | 轻量运行设置，如热点最近同步时间 |
| `style_profile` | 风格规则、个人偏好和样本名称 |

`metric_daily` 使用唯一键更新，重复同步不会重复累计。

## 安全边界

- 凭据只从进程环境读取，并在错误输出中执行脱敏替换。
- SQLite、素材、配置文件和日志默认不进入 Git。
- `/media` 只允许读取项目目录内且已经登记到素材库的文件。
- 网页图片导入会拒绝本地地址和私网地址，降低 SSRF 风险。
- 创建微信草稿需要请求体明确传入授权标记，并对已有成功/失败任务做幂等保护。
